# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

CityLoom is a street, junction and city-map editor written in Rust, compiled to WebAssembly and drawn with Leptos 0.8 (client-side rendering). The pages are `web/index.html` (home: find a place), `web/map.html`, `web/street.html` and `web/intersection.html`. The streets come from OpenStreetMap; the catalogue's rules, rates and thresholds are synthetic placeholders.

## Commands

`just` lists the recipes. The ones used most:

```sh
just test            # cargo test --workspace --features cityloom_server/test-provider + `cargo build --target wasm32-unknown-unknown --workspace --exclude cityloom_server` (cfg(target_arch = "wasm32") code is not compiled by plain `cargo test`); needs `DATABASE_URL` (a Postgres: `just db` starts one and prints the URL; `just db-stop` removes it); the server's tests use `sqlx::test`, a fresh database each
just db              # a throwaway Postgres in Docker (container `cityloom-db`, 127.0.0.1:55432) for the server's tests and the account e2e specs
just check-no-fake   # builds the release server and checks it has no fake provider (CI's server-release job)
cargo test shell::vm # one module; a full test name also works
just build           # release wasm of both modules + wasm-bindgen into web/pkg (gitignored); scripts/build.sh does the work
just prepare         # downloads Geofabrik's Quebec extract into data/ if it is not there (about 1.2 GB; `--refresh` takes a newer one), then cuts the metro area's roads into web/data/metro (needs osmium-tool) and builds the map page's basemap, web/data/basemap/montreal.pmtiles, with Planetiler (needs Java 21+); both gitignored. Nothing needs the road tiles: without them every place, the default one too, comes from Overpass. Without the basemap the map page says so and shows no map
just e2e             # builds the wasm and the server (`cargo build -p cityloom_server --features test-provider`), then runs the Playwright tests in e2e/; `just e2e tests/street.spec.ts` for one spec; `account-server.spec.ts` needs `DATABASE_URL` and fails with a message saying so without it
just deploy          # build, then upload the site to the Railway project cityloom (scripts/deploy.sh; needs the Railway CLI logged in and `just prepare`'s tiles; it builds the wasm and the server for `x86_64-unknown-linux-musl` (cargo-zigbuild and zig, from `just setup-deploy`), refuses a server that holds the fake provider (`scripts/check-no-fake.sh`) and uploads `web/` and the binary; `deploy/Dockerfile` is an Alpine image that only copies and runs it as a non-root user, the server serving `web/`; CI's `deploy` job runs it on every push to main once the other jobs pass, making the tiles itself (cached) and using the `RAILWAY_TOKEN` secret of the `production` environment)
just check           # everything
just format          # rustfmt (rustfmt.toml) + Prettier; `just format-check` only checks, as CI does
just serve           # `cargo run -p cityloom_server` (http://127.0.0.1:8137/; serves `web/` with range requests, as the basemap's PMTiles need; E2E_PORT moves the port, for Playwright too; without `DATABASE_URL` the account side answers 503 and the pages are signed out)
just docs            # the documentation site (website/, Docusaurus, English and fr-CA; pages in website/docs and website/i18n/fr-CA; `just setup-docs` installs its packages once, `just setup` does not): serves it at http://localhost:3000/; `just docs-build` builds both languages and fails on a broken link (CI's `docs` job); CI's `docs-deploy` job publishes it to GitHub Pages, https://alandovskis.github.io/cityloom/, on every push to main once the other jobs pass
just setup           # once: wasm-bindgen-cli (version from Cargo.toml, into .tools), `npm ci` at the root and in `e2e`, Playwright's Chromium
just setup-deploy    # once, for `just deploy`: cargo-zigbuild (into .tools) and the musl target; zig itself is `brew install zig` or `python3 -m pip install ziglang` (`scripts/deploy.sh` checks for it first)
```

CI (`.github/workflows/ci.yml`) runs `just format-check`, `just test` and `just e2e` with `RUSTFLAGS=-D warnings`, so a new compiler warning fails it, its `test` and `e2e` jobs run a Postgres service, its `server-release` job runs `just check-no-fake` (and checks that the check fails a build with the fake provider), and its `docs` job runs `just docs-build`; run `just format` before committing. There is no clippy configuration. `build.sh` strips the name and producers sections (without that the wasm is ~7.6 MB instead of ~2 MB). The `proc-macro-error2` future-incompat warning comes from Leptos dependencies and is harmless.

## Architecture

The code is organised by vertical slice, one folder per feature, and MVVM is used inside each slice:

- `street/`, `junction/`, `map/`, `shell/` each hold what that feature needs: `model.rs` (street, junction: the editing rules, no DOM, no signals, no I/O; edits return `bool` and a refusal carries a reason), `vm.rs` (the view-model), `text.rs` (the words said to a screen reader), the Leptos views, and `tests.rs`. `junction/` also has `geometry.rs`, `read_model.rs`, `frame.rs` and `signal.rs` (the cycle of a traffic signal, one phase per street that has entering lanes in the order of their bearings, and which pedestrian crossings and bike movements run with each phase; `Arm.timing` was added within `city::edits::VERSION` 3 and is saved only once set; version 4 discards the documents of version 3, those with timing included).
- `map/` is the exception to the SVG rule below: the map page draws the city over a MapLibre basemap and no SVG. The layout is placed on the earth by `city::projection` (`Projection`, `for_store`), `overlay.rs` turns the city into GeoJSON places (`hot` ids `s-<uid>` / `j-<uid>`; a street also carries its `class`) and `style.rs` holds the overlay's MapLibre layers (a dotted white `places-pedestrian` line over the pedestrian streets); `editable.rs` says which places the map's open view (the part the panels leave open, `MapEvent::View`) makes editable: a street wholly in it, a street too big for it while it crosses it, a junction whose point is in it; the view-model sends the set with `Mapper::set_editable` (the adapter writes it as feature-state `editable`, `style.rs` mutes the rest) and a press on a muted place opens nothing and says `map-not-editable`; `areas.rs` (`AreasVm`, held by `MapVm`) and `areas_view.rs` are the Area rules panel, the map page's left panel (its toggle is `#inspector-toggle`, `[`, like the editors' inspector, so the shell opens and remembers it) (they use `restriction::draw`; the map owns the restriction UI) (declare, select, rename, rule, redraw, drag corners, delete with Undo); the map tells the page a `MapEvent::Press` (where, and the place, area or corner under the pointer) and `MapEvent::Vertex` (a corner dragged), and Rust decides what a press means; `Mapper::set_restrictions` / `set_draft` / `centre` draw the areas and the outline being drawn; the view-model drives MapLibre through the `Mapper` port. The status line and the checks lead count the streets that break an area rule only when no design check fails. `svg.rs` and `camera.rs` remain only for the home page's hero (`map/home.rs`). A city whose area's roads were not kept has no places and no map: the page says there is no map to show (`NO_ROADS`).
- `city/` is the city (`keys.rs` the place keys, `edits.rs` the edits document; `model.rs`; `Layout::sample()` is the tests' hand-made one, not part of the app, and neither are the sample streets and junctions the editors' unit tests start from: `street::model::fixtures` and `junction::model::fixtures`, compiled for tests only), how it is kept in storage (`store.rs`), `projection.rs` (`Projection`: where a kept city lies on the earth) and the `CityBinding` a page writes back through (`binding.rs`).
- `place/` is where a city comes from: `area.rs` (an `Area` kept under its position), `nominatim.rs` and `overpass.rs` (the requests and readers, pure), `loader.rs` (`Loader`: search, then fetch, import and keep an area's roads, through the ports), `vm.rs`/`view.rs` (`AreaVm`, the home page's place search) and the `prepare_city` export the page scripts await.
- `restriction/` is the area restrictions: `model.rs` (the outline in lon/lat, exact on micro-degrees: `contains`, `valid`, `midpoint`, `inside`; the four `Rule`s and `conflicts` as `Said` data; `Restriction`, `Finding`), `draw.rs` (the pure draw state machine) and `store.rs` (`RestrictionStore` over the `cityloom-restrictions` document, version 1, with a `next_id`: a future version is left alone, a damaged one copied to `cityloom-restrictions-damaged`, a record it cannot read, a field it does not know and any other key are kept as they were, a `version` that is not an integer is a newer build's, each write re-reads and changes one record). A street is inside when its midpoint is; only loaded streets are counted. The Car-free rule forbids exactly `catalogue::CAR_KINDS` (travel, parking, loading; a bus stays allowed), a subset of `catalogue::MOTOR_KINDS`, the list that decides what a pedestrian street has none of, so a pedestrian street never conflicts with it. Restrictions do not depend on tiles or place keys and check whatever layout is loaded. The street page's Checks list a row per area holding the street (`StreetVm::area_checks`). The view-model (`AreasVm`) refuses an invalid ring (`model::valid`) before it adds or updates; the store does not. A speed limit is declared and shown only (streets have no speed, so its row is informational and never counts as a conflict). Known limits: a street page reads the areas once when it opens (stale until reload); the `Storage` port cannot say a read failed, so a failed read looks like an empty document, and a write after it would replace the document.
- `junction/turbo.rs`, `junction/turbo_spiral.rs` and `junction/turbo_ring.rs` (helpers on outlines) are the **turbo layouts** of the junction editor (basic, egg, knee, spiral and rotor, in the four Dutch blocks; the figures are placeholders from secondary sources on CROW 2008, and the unverified ones are marked so in doc comments). A turbo is a layout of the `ROUNDABOUT` control, not a control: `State.turbo: Option<Turbo>` (layout, block, the two main-road arm uids; saved, skipped when `None`, range-checked by `Layout::junction_fits`). `turbo.rs` holds the rules: entry lanes per layout (the layout, not the street, says how many; an arm cars do not enter gets none), lane destinations fixed by the layout (`set_lane_dest` is refused), the main-road candidates (best opposite pair first), the skew of each arm from its template direction (more than 20° refuses the edit and names the arm; 10° or more fails the `turbo-square` check). `turbo_spiral.rs` is the ring as pure geometry, a spiral (CETRA 2016 Fig. 3 and 4): each lane edge is two half circles, one each side of the translation axis (57.5° from the main road with four arms, 65° with three, mirrored for left-hand traffic), their centres shifted apart along it (the island's by Δv, every other edge's by Δu); at the axis the inner edge of a lane on one half meets the outer edge of the same lane on the other within 50 mm (a test pins it for all four blocks), so a lane goes on as the next lane out, the outermost lane leaves the ring and the innermost begins at the island. `ring_shape` gives one open `RingLane` per half and ring lane, in the direction of traffic (anticlockwise for right-hand traffic: the ahead half is on the clockwise side of the axis), the closed outlines of the island, the carriageway and the cycle track (stepping along the axis at the two tips), and the dividers: each half's R2/R3 arc cut where a street's carriageway meets the ring (`Mouth`), so a piece begins and ends at a street, and none shorter than 3 m. `spiral_walk` is a movement's line round the ring: it keeps its lane, steps out a lane at each tip, and in the outermost lane leaves at the tip for the first street after it (any other street is unreachable from that lane); `turbo_path` tries a lane further in when the lane the entry feeds cannot reach the street (an egg's or knee's lone lane). A test checks that no movement of any layout, block and side of the road crosses a divider (the dividers are cut at every street, so an inner lane may leave across the outer lane at any street: no lane is checked). `turbo::uses` is the lane table: a main arm's lanes by place (first left and through, last through and right, a middle one through only), a side arm's outermost lane (right in right-hand traffic, left in left-hand) turns toward the outside only, a lone lane serves every turn. UNVERIFIED (spec amendment 2026-10-13, J1 to J7): which end of the axis leads (so where the tips lie among the streets, and which arms the lane table treats as side arms: if it flips, main and side swap), where a divider begins and ends, the spiral and rotor blocks (the one-axis block is the Egg, Basic and Knee block; a third lane is an extension), where a movement leaves at a tip, and the egg's and knee's lone lanes. `settle_table_and_boxes` settles a turbo (dropped when the control, the arm count, the skew or the room for an entry no longer suit it; no bus lane across the island, no queue jump, crossings kept 6 m from the ring, lanes set), `read_model::layout` widens each entered arm to the layout's lanes (`TURBO_ENTRY_LANE_MM`, 3.5 m, a placeholder; a layout whose widened entry would pass its street's property line is refused as `TurboEntryTooNarrow`, naming the arm, and a saved turbo that no longer has the room is dropped like one past the skew limit) and builds the ring on the block (a turbo that fits no block is refused as too big), and `RingView.lanes` / `.dividers` carry the ring to the plan (the dividers open, a painted double white line in pieces, drawn in `var(--ink-2)` because the plan's road is white in the light theme) and to the 2.5D (`shared::iso::paint`; the 2.5D does not draw the widened entries, so its sidewalks still stand where the plan paves). `read_model::choose_turbo` is the one test both `set_turbo` and `turbo_options` use, so a layout offered is a layout accepted. The inspector's layout choice is a WAI-ARIA radio group (one tab stop, Arrow/Home/End choose, decided by the pure `keys::radio_choice` / `radio_tab_stop`; re-choosing the chosen layout is a silent no-op).
- `shared/` is the kernel: catalogue, units, atlas, symbols, the ports (`Announcer`, `Storage` (`recall`, `remember`, `keys`), `Scheduler`, `Mapper` (with `MapEvent`, `NoMapper`, `FakeMapper`; `set_restrictions`, `set_draft` and `centre` beside the places and the view, `set_insets` and `set_editable` for the open view; `MapEvent::View` reports it) and their fakes in `ports.rs`), `platform.rs` (their browser side; `BrowserMapper` wraps the JS adapter `web/basemap.js`), `core.rs` (`Core<M: Presents>`, the model plus a version signal plus a cached view; `view()` is tracked, `view_now()` is not, so use it in commands), `keeper.rs`, `shortcut.rs`, `bind.rs`, `iso/` (what the street's and the junction's 2.5D really share, with no slice dependency: `format` (`esc`, `f1`), `shading` (`shade_filters`, the `<filter>` markup; each slice keeps its own ids) and `paint` (pavement paint on the ground plane in millimetres, independent of any projection: `quads` turns a ground polyline and a `Style` (`Paint`, `Pattern`, `double`) into quads, `class` gives the CSS classes; the line width 120 mm, double-line gap 120 mm, dash 3 m and gap 6 m are its constants)), and `testing.rs` (test-only HTML helpers). `shared` must not depend on any slice. The ports also include `Fetcher` (HTTP), `Importer` (the OSM reader, a separate wasm module), `Account` (the sign-in state and the account API) and `Navigator`.
- `cityloom_server/` is the server (a workspace binary and library, not built to wasm; `just test` type-checks the wasm side with `--exclude cityloom_server`): `static_files` (the static site: types, ranges, 403 for a path leaving `web/`, 400 for a bad escape, `index.html`), `config` (the environment into a typed `Config`, `.env.example` lists the variables; `AccountSide::Off(OffReason)` when `DATABASE_URL` or a key variable is missing or invalid, which makes `/auth/*` and `/api/*` answer 503 while the site is served; the key fields are `Zeroizing`; a database that is down at start-up is not `Off`: the pool is lazy and `require_ready` answers the same 503 until a background task has migrated it), `crypto` (versioned master keys, a data key per user wrapped under the current master key, AES-256-GCM sealing as `version ‖ nonce ‖ ciphertext ‖ tag` with `table.column.<row id>` as associated data, the identity lookup HMAC), `accounts` (the rules over a `Repo` trait: sign in, link, unlink, storage choice, delete; `MemoryRepo`), `db` (`PgRepo` seals before it writes and opens after it reads; migrations in `cityloom_server/migrations`; `db/rotate.rs` is `rewrap` / `rehash`, run by `commands.rs` as `cityloom_server rewrap|rehash` (only `rehash` reads `OLD_LOOKUP_KEY`); `rewrap` prints `resealed N data keys` and is safe only in this order: deploy with the new key added and `DATA_KEY_CURRENT` set to it, run it (on Railway: `railway ssh`, then `/app/cityloom_server rewrap`) until it resealed 0, and only then remove the old key, because a server still on the old current key keeps wrapping new users under it and `rewrap` does not see them; `rehash` needs `OLD_LOOKUP_KEY` and the server stopped, and prints how many identities it checked, rehashed and found already on the new key), `session` (`__Host-cityloom-session`, 30 days sliding, refreshed after a day), `flow` (`__Host-cityloom-flow`, an encrypted cookie, ten minutes, `safe_return`), `providers` (one OpenID Connect client for OpenStreetMap, Google, Microsoft and Apple; `providers/apple.rs` signs and renews Apple's client secret; `providers/microsoft.rs` checks the issuer against the token's own tenant), `auth` and `api` (the routes), `app` (the router, `Account`, the Origin check on changes, the rate limit keyed on the rightmost `X-Forwarded-For` entry (the one Railway's proxy appends; `client_address`), `require_ready`, request logs without queries), `fake_provider` (feature `test-provider` only, never in a release: `scripts/check-no-fake.sh`; a test picks who signs in with the `fake-login` cookie). Logs never hold a token, code, cookie, email, `sub` or label. Callback outcomes go back as `#account=<new|signed-in|linked|already-linked|conflict|cancelled|failed>` (`conflict` adds `&provider=<slug>`; the shell says a generic sentence when the slug is missing). A callback with a `state` that is not the flow cookie's leaves that cookie alone (it is another tab's live flow). The server's own tests are in `cityloom_server/tests/` (`auth_flow`, `api`, `db`, `no_plaintext`, `rotate`, `providers`, `static_files`, `unavailable`).
- `account/` is the Account page (`web/account.html`, `web/account.js`, `mount_account`): `vm.rs` (linked sign-ins, link / unlink, the storage choice, the in-page deletion confirmation; the choice is shown first, and focused, when it has not been made; it is only recorded, nothing reads it yet), `view.rs`, `text.rs`, `i18n/{en,fr}.ftl` (`account-*`). The header's Sign in button and menu are the shell's `session` (`shell/session.rs`, `session_view.rs`, messages `session-*`, slot `#session-slot` on all four app pages and the Account page; "account" in the shell's markup (`#account-btn`, `.account`) is the SETTINGS menu). `Ports.account` is the `Account` port (`me`, `providers`, `set_storage`, `unlink`, `delete`, `sign_out`; `AccountError` keeps the status; `FakeAccount`, `test_ports_full()`), and `Page` gained `path()` and `take_fragment()` (the callback's outcome is read once from the address and removed).
- **Dependency rule:** a slice may use another slice's `model` (junction uses the street model; city uses both), `city::store` / `city::binding` / `city::projection`, `restriction::store`, `shell::Target` and `shared`; it must never reach into another slice's `vm`, views or text. New code goes in the slice that owns the feature, not in a layer folder.
- **View-models** expose presentation-ready reactive getters and take commands. They reach the browser **only through the ports**, so they are tested natively against `test_ports()` / `test_ports_with_time()`.
- **Views** bind to a view-model and forward events; they decide nothing. Rendering is by pure functions returning SVG strings (`plan_svg.rs`, `street/svg.rs`, `street/iso/`, and `map/svg.rs` for the home hero only) set with `inner_html`; pointer and keyboard logic are pure state machines with tests. `shell/view.rs` is the exception: it binds the static markup the pages share to `ShellVm` with web-sys listeners and effects.
- The street page's drawing has two views: the section (`street/svg.rs`, which is edited) and the street in 2.5D (`street/iso/`, read-only: `projection.rs`, `raised.rs` (heights, slabs, curbs, their order), `solids.rs`, `surface.rs`, `markings.rs`, `symbols.rs`, `paint.rs`, and `mod.rs` which puts the layers in order). The 2.5D is an oblique projection (`iso::Projection`, not `city::projection`'s: a 40 m stretch, `STRETCH_MM`, receding up and right) of the same `View`; each piece is an extruded strip with its height from `HEIGHTS` (the curb steps come from `curb_height_mm`, and `curb_edges` / `curb_width_mm` are shared with the section), the things that stand on the pieces are boxes (`Solid`: a tree's trunk and crown, a bus shelter, a post on a curb) that a piece narrower than `MIN_SOLID_PX` (20 px, on screen) loses, as it loses its symbol, the markings lie on the roadway, and the selected piece gets an outline (`iso-sel`). The drawing is built in layers, each its own `<g>`, in this order: `<defs>`, the ground (`iso-ground`), the surface (`iso-surface`: the top of every roadway piece, each in its `iso-piece` group with `data-uid`), the markings (`iso-markings`), the raised layer (`iso-raised`: every strip standing above the roadway, with its faces, lowest to highest, so a sidewalk or curb covers the paint where they meet), the solids, and the selection outline. The markings are inferred from the pieces as shown (`markings(v)`: a pure function of the `View`, following MTQ Tome V and its Manuel technique sur le marquage routier): yellow double solid between opposed driving lanes and beside the lane a contraflow bus or bike lane runs against (its far side can be white), white broken between driving lanes of one direction, white double solid between a driving lane and a bus lane running with it, single white beside parking, loading, a shoulder and a bike lane, a broken yellow line down a two-way bike lane, and nothing against a curb (a bike lane's own included), sidewalk, planting or median; the lines come from the neighbouring pieces, and each lane carries a symbol at `ARROW_AT_MM` (a lane arrow, the bus diamond with "BUS", the bike symbol), drawn as polygons from `symbols.rs`, whose sizes are estimates pending the official Répertoire des dispositifs drawings; a piece narrower than `MIN_SOLID_PX` keeps its lines and loses its symbol. Paint is `iso-paint white|yellow` (never `iso-top`/`iso-front`/`iso-side`), coloured by `--iso-paint-white` / `--iso-paint-yellow` (a 0.5 px edge in the light theme keeps it at 3:1 on the surfaces) and `CanvasText` in forced colours; nothing about it is stored. Known limit: the hover outline of a roadway piece is hidden where paint covers its edge (its title and the selection outline still work). Slab rises (a piece standing above the roadway, such as a sidewalk, a median or planting, and the curbs with them) are drawn `RISE` (3) times as high as they stand, so they read at the scale of a whole street; what a curb stands above its own piece (a bike lane's divider) is drawn at true height (`curb_top_mm`); the solids keep their size and sit on the drawn tops. `HEADROOM_MM` (5 m) leaves room above the far end for the tallest crown (a test guards it), so a street with no trees shows an empty band there. The 2.5D carries its own screen-reader label (`svg-iso-label`, `iso_label`). The mode is `StreetVm::mode` (`ViewMode::Section` | `Iso`), kept per browser under `cityloom-street-view` and announced; the toggle (`page::ViewToggle`, a fieldset of two `aria-pressed` buttons in `#view-mode-slot` (`.view-mode-tools`), on the street name's line: the title card is a grid whose first row holds the name and the toggle, at the name's height, so the head is no taller for it, even with Linux's wider fonts) or `V` switches it. `V` is decided by the pure `keys::switches_view` (not with Ctrl, Cmd or Alt; not on a repeat, while composing, in a field or editable text, or when the event was already handled; it goes by the key, so a layout without a Latin V does not get it) and finishes a drag under way first, keeping what it has shown as an undoable edit. In 2.5D the pointer handlers and handles are not mounted; the keys on `#wrap` still edit the street. The group's `min-height` is the taller of the two views, so switching does not make the card jump. The faces turned from the eye are shaded by two SVG filters the drawing carries in its own `<defs>` (`SHADES` in `street/iso/raised.rs`: 0.9 front, 0.78 side, in sRGB, built by `shared::iso::shading`), not by CSS `filter: brightness()`, which Safari may not apply to SVG shapes (not checked in Safari either way). The drawing's heading (`page::DrawingHeading`, in `#h-drawing`) and the group's label name the view shown; only the button of the view not shown carries `aria-keyshortcuts="V"`. Under 900 px the toggle keeps the edge tab's width (`--tab-w`) clear at the right, since the Notes' tab is fixed at the window's edge; in forced colours a pressed `.unit` keeps an outline in `Highlight`; the toggle is not printed. Known limit, older than the 2.5D: at 1440 px the section (`Geometry::fit`'s floor, 680 px) is wider than its group (672 px) and overflows the scroller by 2 px, so the swipe cue shows.
- **Pedestrian streets.** `StreetClass::Pedestrian` is derived, not chosen: a street with no motor piece (`catalogue::is_motor`, `MOTOR_KINDS`: `travel`, `parking`, `loading`, `bus` or `shoulder`, as its own kind or in any time window; bike lanes are allowed) is pedestrian, and `Street::settle_class` keeps `class` and `class_before` (the class it had before) true after every edit and when a street is built (`imported`, the editor's `push`/`from_street`); the editor keeps both in each history state, so undo and Start over restore them exactly, and giving a pedestrian street a motor piece restores `class_before` (or Local). `Editor::make_pedestrian(kind)` (the street page's Make pedestrian menu, `page::MakePedestrian`: sidewalk, planting or terrace, `catalogue::PEDESTRIAN_KINDS`) turns every motor piece into that kind at its own width in one undoable edit (bike lanes stay), and focus returns to `#wrap`; there is no command back, and an edit that changes the class says so in the same announcement (`text::class_change_text`). A pedestrian street's `access` check wants an unbroken run of adjacent sidewalks of `ACCESS_LANE_MM`, and `edges` is not asked. A junction arm is pedestrian when its street is (`Arm::is_pedestrian`): `normalize` gives it no crossing and no lane goes to it (when it regains traffic it gets the default crossing back, and the other arms' lanes regain it where the default uses serve it), `Refusal::CrossingOnPedestrian` refuses one, its pieces are drawn from the mouth as walking surface (the 2.5D stands them all at sidewalk height), the checks skip it, and with at most one street of traffic (`model::traffic_arms`) the junction runs uncontrolled (`model::in_force`, the read side only; the kept `control` returns) and the inspector says so. The map names an unnamed street by its current class. A bike-only street is pedestrian, a bus-only or shoulder-only one is not; the Car-free rule is narrower and still allows a bus.
- **Entry points** are in each slice's `mod.rs` (wasm-bindgen exports: `Plan`/`open_junction`/`mount_page`, `Sheet`/`open_street`/`mount_street_page`, `mount_map(basemap)`) and `lib.rs`. A page script (`web/app.js`, `junction.js`, `map.js`, each tiny) only loads the module, sets up the hatch `<defs>` (not `map.js`: it has no SVG; it creates the basemap with `createBasemap` from `web/basemap.js` and passes it to `mount_map`), and calls `mount_*` and `.mount_shell()`.

Translation: English and Canadian French (fr-CA) on all four pages (home, map, street, junction) and the shell. The engine is `shared/i18n.rs` (`Locale`, `Resources`, `Args`, `I18n` with `tr`/`tr_now`/`locale`/`locale_now`/`set`/`missing`, `detect`, `LANG_KEY`, `typography`); the slices that own messages (shell, street, city, map, place, junction, restriction) each have `i18n/{en,fr}.ftl` and a `RESOURCES` const, registered only in `lib.rs::i18n_for` (`i18n_browser` picks the starting language). Text functions take `&I18n`; views use the tracked `tr`/`say` so they follow a switch, commands use `tr_now`/`say_now`. The model never holds wording: it says things as `Said` data (a key and `Arg`s, `shared/said.rs`; an `Arg` can be a `Said` itself, `Arg::Said`, or a message lowercased, `Arg::MsgLower`) that `say` renders in the current language, so history follows the switch; the names the app invents (a place, a street's title, its ends, the class words, "unnamed" forms) are `Said` too, with their messages in `city/i18n`, and `junction::model::State.label` is a `Said` that is not saved (`serde(skip)`). The language switch is in the shell (`ShellVm::set_locale` keeps `cityloom-lang` and sets `<html lang>` through the `Page` port); every page's markup carries `data-i18n*` attributes that `shell/view.rs::apply_translations` fills, the Language row and a head script that sets `<html lang>` (each page's header owns its `<title>`). Message keys are registered globally, so a slice words another slice's messages only by key, through `Said`/`Arg`, never by importing its text: the map says the junction's `jn-control-*`, the street and junction pages say `city-*` (the invented names), and `class_key` (`class-*`, in `city/i18n`), `kind_key` and `atlas::name_key` / `note_key` (in `street/i18n`) name the catalogue's classes, kinds and measures. A junction that cannot be drawn gets its page from Rust (`mount_bare_shell`, `junction_exists`), so `web/junction.js` holds no wording.

OpenStreetMap: the workspace has four more crates. `cityloom_server` is the server described above. `osm_network` is the plain network type (serde only). `osm_import` runs osm2streets (git dependencies, so they stay out of the editor's wasm) and fills it; it builds as its own wasm module (`web/pkg/osm_import*`), which `web/city.js` loads on first use and offers to the editor as `window.cityloomImportOsm`. `city/import.rs` turns a network into a `Layout` (the nodes and edges a `City` holds; the tests' hand-made city is `Layout::sample()`): roads become streets (`Street::imported`, with their own `name` and a `StreetClass` from the road's `highway`; a road with no lanes is left out, and a place's title is derived from the streets that meet there), a meeting of 3-5 arms the junction editor can draw becomes a junction (arms leaving within 30 degrees are spread; a meeting that cannot be drawn is a plain connection). A lane buffer keeps osm2streets' own type (`osm_network::BufferType`, `Lane.buffer_type`; osm2streets' sidepath zipping, which would insert a planter for a separately mapped way, is not among the transformations the importer runs, and every buffer on the Plateau is a curb it inferred) and `kind_of` makes it planting only for a planter or a verge: a curb, paint, posts, a barrier, a shoulder (the catalogue's `shoulder` is a motor kind, and osm2streets gives that name to any lane open to every mode) or a buffer of no known type is the neutral `buffer` kind (the last of `KINDS`, so stored indices hold: concrete or asphalt, mode `Neutral`, which is in no mode's share of the width (the width table gives it a row of its own only on a street that has one) and is not `is_roadway`, no line painted against it); a curb between a bike lane or a sidewalk and a driving, parking or transit lane is that piece's own, its width added to the piece's (up to its maximum), since the editor draws a bike lane's and a sidewalk's curb inside the piece against a road piece. What a curb adds past the maximum of the piece it joins stays beside it as a buffer, so the street keeps its width. A remainder under the buffer's 150 mm minimum goes to the road lane beside the curb, so the street keeps its width. A 150 mm buffer is selected by keyboard, not by pointer: the boundary handles cover it (`e2e` `pressablePiece` looks for a piece of 40 px or more). A median is only the space between two merged carriageways. This changes the width (`row_mm`) of most streets (150 of the 153 of the Plateau extract, which made every curb a 600 mm median before importer version 5), and a saved edit applies only when `row_mm` matches; so the importer also works out the widths a street had before (`EdgeDef.legacy_rows_mm`, never saved, empty where none differs): under version 4 (every buffer its own median, nothing merged), with a two-way bike lane as the one-way lane it was read as before the ways of a track were fetched (half the width), and both together; a record whose `row_mm` is the width it has now or one of those applies (the width the street has now is tried first). A record taken by the old width is shown as saved, medians and all, and keeps that width on every write (its pieces add up to it, so no check fails), and is found by it at every import; Start over gives the street the width it has now. One matching neither stays an orphan (`city::store` pins these, and `real_city` that all 150 changed streets are found). `city::edits::VERSION` stays 5: the record's shape is the same. A bike track that runs both ways is one bike lane with no direction (`osm_network::Way::Both`, `direction: None`, the editor's two-way): `osm_import` reads it from `cycleway:<side>:oneway=no` and, for a track mapped as ways of its own (`cycleway:<side>=separate`), ties the road's side to the tracks (`highway=cycleway`, or a `path`/`footway` with `bicycle=designated`) that belong to it, before osm2streets runs: the track belongs to one carriageway (motorway to unclassified, residential, living_street, busway, and `service` other than driveway, parking_aisle, drive-through and alley), chosen among those it runs along (60% of five points along it lie within the road's extent, 1.5 to 16 m from its centre line on a side and within 30 degrees of it), the road that says `separate` on that side first, then the nearest, then the lower way id; the side is two-way when no such track is one-way (a track 5 to 16 m from a tagged street that really follows a railway or river is claimed all the same; each piece the clip cuts a way into is judged on its own) (`oneway:bicycle` / `bicycle:oneway` before `oneway`) (osm2streets keeps neither those ways nor a lane's two directions; the tracks are fetched with the roads, in the metro tiles by `scripts/metro_tiles.py` (cycleways, and the paths and footways designated for bicycles, found by a second `osmium tags-filter` pass because one expression cannot AND two tags) and in `place/overpass.rs`'s query, and `osm_import` leaves every cycleway, path and footway out of what it hands osm2streets, so they are neither streets nor junctions), then joins the two opposite lanes osm2streets makes of a `oneway=no` side. A place is flagged only for checks a change makes worse than the city first laid out. Where a place's roads come from (`place/loader.rs`): from the one metro tile whose core holds its centre (`place/tiles.rs`: `data/metro/index.json` names the grid and the tiles there are; a tile holds every road (and bike track mapped as a way of its own) reaching into its core widened by 0.5 km, so one tile covers an area's 0.4 km reach; an area is kept as made from its tile's checksum plus the importer's version, `tiles::IMPORTER_VERSION`, which is raised when the importer's output changes for the same data, so that a changed tile or importer has the area read again; an area read from Overpass keeps no checksum and is not) and, if there is no such tile or it cannot be had, from Overpass. Whatever the source, the importer keeps only the area's box. `CityStore::current` opens the chosen area (`cityloom-area`), the default one (the Plateau Mont-Royal in Montréal, made like any other area) before one is chosen (until its roads are kept its city has no places); the area's network is kept under `cityloom-network:<key>`; the edits are not kept per area (see Persistence). An edge keeps the road's centreline (`EdgeDef.shape`, `EdgeView.shape_mm`, in layout millimetres) and the layout remembers where it sits on the earth (`Layout.origin_m`, `CityView.origin_m`), so the map page can draw it over the basemap; only the editors and the home hero still draw an edge as a straight line between its nodes.

Persistence: a page opened from the map (`?junction=3`, `?street=7`) edits one place of the city. `CityBinding` writes it back through `CityStore` (against the city as stored *now*, so another tab's change is not overwritten) behind a 250 ms debounced `Keeper`; `flush()` is called on `pagehide`. Without a place of the city the page goes back to the map. A write failure is said once. The edits of every area live in one document, `cityloom-edits` (`city/edits.rs`; `version` 5), whose records are keyed by what the place was made from (`city/keys.rs`): `n<id>` for a junction (its smallest OSM node), `w<id>~n<id>~n<id>` for a street (its smallest way, then its two ends' keys). An end that is no OSM node, where the road is cut at the area's box, is `x`, and the key then ends with the way the street leaves its real end in four compass words (`w7~n2~x~e`), measured from the layout node to the first point a metre along osm2streets' trimmed centreline: osm2streets moves both when a junction's cluster changes with the box (up to 60 degrees measured on the Plateau), so the word can flip between areas; matching by ways, nodes and bearing then finds the street again, and the residual risk (an exact key, which outranks the bearing check, naming another piece after a flip; none seen over 11 probed areas) waits for the proper fix, anchoring the key on the next OSM node along the way; the halves of a closed way (two streets of one way between the same nodes) end theirs with the way each leaves its first end. A key two places of the layout still share is no key: such a place is never written (the write says it was not kept), so a write never reports kept an edit that cannot come back. A place is written alone (one record, in the document as kept: every other record, one this build cannot read too, is written back unchanged), replacing the record it took its edit from when that had another key. A record is matched to a place by its key, or failing that by the OSM ways and nodes it was made from (of pieces that overlap it as much, the one leaving a shared end the same way; a piece leaving a shared end 45 degrees or more from the record's bearing does not overlap it); a junction's arm finds its street among the streets at the junction by key, or by a shared way leaving the same way. A saved street is matched on its width (`row_mm`), not its class: an edit changes the class (a street made pedestrian), and the street record carries `class_before` for that. Records of places not in the area opened, or matched by none, are left as they are. An edit follows its place into another area or tile that holds it when the importer makes the place the same there (`osm_import/tests/real_city.rs` measures it on the Plateau tile in areas shifted 150 m east, west, north and south: at least 95% of the places made the same follow, and no place takes the edit of another, which each place's own mark checks); where osm2streets builds it otherwise (roads merged into another width, a junction with other arms) the record stays an orphan, retried at each load, with no UI yet. The positional uid (`?street=7`, the map's `s-<uid>` hot ids) stays internal and the addresses do not change. A document that cannot be read is copied to `cityloom-edits-damaged` (unless a copy is kept already) before the first write; one written by a newer version is neither read nor written over; a test pins the shape a record is written in, so a change to `Street` or `State` is a decision about `version`. A document of version 3 or older is handled as a damaged one (copied to `cityloom-edits-damaged` unless a copy is kept, then replaced on the first write); version 5 adds `State.turbo` (additive and skipped when `None`), so a version 4 document is read as it is and written as version 5; the per-area saves of earlier builds (`cityloom-city:<area>`) are no longer read or moved and stay in storage. Accepted minors: a second damaged document is dropped when a copy is already kept; the golden test pins only the fields the sample records write (not `None`-skipped ones); loop halves leaving their first end within one quarter share a key and are refused.

## Conventions and gotchas

- E2E tests (`e2e/tests/*.spec.ts`, Playwright) cover each page: `shell.spec.ts` runs the same checks on all three, plus one spec per page. `fixtures.ts` makes every test fail on a page error and gives each a fresh browser context (empty storage), starting on the Plateau (an automatic fixture serves its metro tile, and the context its basemap, so there is no network); the editors are opened by the address the map gives a place (`openStreet`, `openJunction`, from `placesOnMap`: the map page has no list of places; it has the Area rules panel on the left and the Notes on the right with their tab); `home.spec.ts` stubs Nominatim, Overpass and the metro tiles with `page.route`; `world.spec.ts` serves a one-place tile from `e2e/fixtures/plateau.osm.pbf`. `junction.spec.ts`'s turbo tests serve a one-crossing tile, `e2e/fixtures/turbo.osm.pbf` (`TURBO_PBF`), because no junction of the Plateau tile has room for the basic layout. They run against the built `web/pkg`, so rebuild after changing Rust (`just e2e` does). `restrictions.spec.ts` declares an area by clicks and by keyboard (the map focused, Enter places a corner at the centre, Shift+Enter closes). Pointer behaviour (drags) is only covered here, not by `cargo test`.
- E2E runs against `cityloom_server` built with `--features test-provider` (`playwright.config.ts` starts `target/debug/cityloom_server` with fixed test keys and `FAKE_PROVIDER=1`, and the caller's `DATABASE_URL`); `fixtures.ts` ignores the console errors the browser logs for `/api/me` and `/api/providers` (401, 404 or 503 are normal for a signed-out visitor), and a spec that makes `/api/me/*` fail on purpose annotates itself `failing-account-api`. `account-server.spec.ts` signs in through the fake provider with a unique `sub` per test and needs `DATABASE_URL`; `account.spec.ts` serves the Account page with stubbed answers and needs no database.
- The map page's e2e: every test serves `e2e/fixtures/plateau.pmtiles` as the basemap (`serveBasemap`); `mapReady(page)` waits for the places, and the map is MapLibre in a WebGL canvas (`window.cityloomMap`), so what the pointer does on it is covered only there. `E2E_PORT` moves the server and Playwright off 8137.
- Adding a string: add the message to both `.ftl` files with the same id and variables (the parity test fails otherwise). Write whole sentences with named placeables, never concatenate pieces; plurals use selectors (`[one]` / `*[other]`). Write an ordinary space before `:` in the `.ftl`; the engine makes it non-breaking. fr-CA follows the OQLF: no-break space before `:` and inside `« »`, none before `;` `!` `?`. Terms are in `docs/glossary-fr-ca.md` (with those still to confirm). Lengths and typed numbers go through `Units::*_in(…, locale)` and `parse_number`, never `format!("{:.1}")`.
- `src/i18n_guard.rs` reads the files listed in `MIGRATED` with Rust's lexer and fails on any wording in them; add a file there when its slice migrates. A literal that only looks like a word (a CSS class, a media query) goes in `ALLOWED_LITERALS` with its reason. The same guard fails on any kebab-case literal in those files that is not a message in both languages (a mistyped key would show as itself); one that is not a message (an element id, a CSS class) goes in `NOT_MESSAGE_IDS` with its reason.
- Still English: `web/credits.html` (static, no wasm), OSM data (street names, classes as the data has them), the basemap's labels and MapLibre's own control strings. Every page is translated and builds its shell with `i18n_browser`; `src/i18n_guard.rs` lists the migrated files in `MIGRATED` (`LEFT_OUT` names the few left out and why; a file of map, place, junction or city in neither list fails a test) and also fails on a dead allow-list entry.
- The e2e fixture stores `cityloom-lang=en`, so specs start in English whatever the machine's language is; `language.spec.ts` switches language. Playwright reuses whatever already listens on the port, so a stale server (or `just serve`) gives false results: run `E2E_PORT=8291 just e2e` when something holds 8137.
- Logic belongs in Rust; JS in `web/` stays start-up glue. Do not add logic there. The one exception is `web/basemap.js`, the adapter that owns the MapLibre map (the vendored MapLibre and PMTiles are in `web/vendor`).
- Add view-model behaviour with a native test against the port fakes. Component tests render to HTML on the host (each slice's `tests.rs`, Leptos `ssr` as a dev-dependency; helpers in `shared/testing.rs`); `shared::platform::browser_ports()` also works natively (thread-local recorders), which is how those tests read what was announced.
- Non-`Send` values inside reactive closures go in `StoredValue::new_local`; views take a `Copy` handle (`junction::watch::Watch`, `street::watch::SheetWatch`) over an `Rc<…Vm>`.
- `any_spawner::Executor::init_wasm_bindgen()` must run at the top of every `mount_*` function before any component creates an effect.
- `#![recursion_limit = "1024"]` is needed for the Leptos `view!` macros. New web-sys APIs need their feature added in `Cargo.toml`.
- Versioning: the product's version is `version` in the root `Cargo.toml` (semantic versioning), shown in the footer of the four app pages (`<footer class="site-foot">`, `data-version`, filled by `shell/view.rs::apply_translations`). Every pull request raises it (major: breaking, minor: a feature, patch: a fix) and runs `cargo update -p cityloom_editor` for `Cargo.lock`; CI's `version` job (`scripts/check-version.sh`) fails the PR otherwise. `credits.html` is static and shows none.
- Test-driven: write the failing test first. Commit each change separately once the tests pass.
- Checking in a real browser: a tab driven in the background throttles timers to ~1 s and pauses `requestAnimationFrame`, and `.focus()` does nothing (no document focus). Use microtask waits rather than timers, and expect focus-dependent behaviour to be unverifiable there. After rebuilding, bust the cache with `fetch(url, {cache: 'reload'})` for the wasm, the glue JS and the page script, then reload.
