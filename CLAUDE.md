# CLAUDE.md

CityLoom is a street, junction and city-map editor in Rust, compiled to WebAssembly and drawn with Leptos 0.8 (client-side rendering). Pages: `web/index.html` (home: the person's projects), `web/about.html` (About CityLoom, with the city of the project opened last behind it), `web/map.html`, `web/street.html`, `web/intersection.html` (and `web/account.html`, `web/credits.html`, `web/timeline.html`, a project's milestones, `web/share.html`, a project's share links or a share link being opened, and `web/compare.html`, two designs (the baseline or a scenario) of one street or junction side by side, with what differs in the second; read-only, opened by the Compare link of a street's or junction's scenario panel). Every page's top bar links Projects (`index.html`) and About (`about.html`), the page's own `aria-current="page"`, and the logo goes to `index.html`; there is no Map link: a map is opened from its project. Streets come from OpenStreetMap; the catalogue's rules, rates and thresholds are synthetic placeholders.

Layout: every crate lives in `crates/` (`cityloom_editor`, the wasm editor, whose `src/` the paths below name as `src/…`; `cityloom_model`, the street network the importer makes and the street as the city keeps it, `cityloom_report`, `cityloom_report_pdf`, `cityloom_server`, `citymodel_builder`, which also holds the OpenStreetMap importer); the root `Cargo.toml` is only the workspace. The product's `version` is in `crates/cityloom_editor/Cargo.toml`. `web/`, `e2e/`, `scripts/`, `website/` and `data/` stay at the root. Other paths below that start with a crate name (`cityloom_server/…`, `citymodel_builder/…`) are inside `crates/`.

## Commands

`just` lists the recipes. The ones used most:

```sh
just test            # test-host (cargo test --workspace, test-provider feature; needs DATABASE_URL) + test-wasm (wasm32 build of the rest: cfg(wasm32) code is not built by `cargo test`); CI runs them as two jobs
just db              # throwaway Postgres in Docker (127.0.0.1:55432), prints the URL; `just db-stop` removes it
cargo test shell::vm # one module; a full test name also works
just check-no-fake   # release server must hold no fake provider (both CI workflows' server-release job)
just build           # release wasm + wasm-bindgen into web/pkg (gitignored)
just prepare         # downloads Geofabrik's Quebec extract (~1.2 GB) into data/, makes the network tiles in web/data/metro (osmium-tool keeps the roads, the importer reads
                     # them once, the network is cut into JSON tiles), packs them into data/montreal.citymodel; all gitignored; args pass through (--refresh). A place no tile holds is "not covered": without tiles no place opens
just pack            # citymodel_builder pack only; `cargo run -p citymodel_builder --release -- tiles|pack` runs one step (`fixture` and `import` turn one OSM file into a tile or a network)
just e2e-fixtures    # imports e2e/fixtures/*.osm.pbf into e2e/fixtures/generated/*.json (gitignored); the browser recipes run it first
just test-scripts    # scripts/include/tests (the issue system's consistency test and the CI selector's); CI's `test` job runs it
just e2e-ui          # UI tier of the browser tests (e2e/tiers.json): one page, network stubbed, static server only; no database, no archive; builds first
just e2e-integration # integration tier: the real server and a Postgres (needs DATABASE_URL): account-server and sync specs; builds first
just e2e-archive     # E2E tier: packs the e2e fixtures into target/e2e-archive and runs archive, delivery and serve specs, and the map and street specs again, against a fresh server that unpacks it (E2E_ARCHIVE=1); builds first; E2E_PORT moves the port
just e2e             # builds wasm and server, then the three tiers; with arguments only those specs (`just e2e tests/street.spec.ts`), whatever their tier; the integration tier needs DATABASE_URL
just deploy          # build and upload to Railway (needs the CLI logged in, `just prepare` tiles, zig; musl build; refuses a fake-provider server)
just check           # everything
just format          # rustfmt + Prettier; `just format-check` only checks, as CI does
just serve           # server on http://127.0.0.1:8137/ (E2E_PORT moves it); without DATABASE_URL the account side answers 503
just docs            # Docusaurus site in website/ (English, fr-CA) on :3000; `just docs-build` fails on a broken link; `just setup-docs` once
just setup           # once: wasm-bindgen-cli (version from Cargo.toml), `npm ci` at the root and in e2e, Playwright's Chromium
just setup-deploy    # once, for deploy: cargo-zigbuild, musl target; zig via `brew install zig` or `pip install ziglang`
```

CI is two workflows, each running `just format-check` and `just test`, and `just e2e` (presubmit: the UI and integration tiers only) with `RUSTFLAGS=-D warnings`, so a new compiler warning fails either: `.github/workflows/presubmit.yml` checks a pull request, and `.github/workflows/postsubmit.yml` checks main in full once it is merged and then deploys it (a manual run of it does the checks and never deploys); run `just format` before committing. A change to documentation alone (`website/**`, `docs/**`, `*.md`, `LICENSE*`: the `paths-ignore` of each, kept in step with the `docs` rule of `scripts/ci/spec-map.json`) does not start either. Presubmit's `changes` job runs `scripts/ci/ci_changes.py` first: a pull request runs the Rust unit tests of the crates its files touch and of the crates that depend on them (`cargo test -p`, read from the crates' manifests by `ci_changes.py`; the wasm check and the release-server check follow the same crates, and a file every crate reads, such as `web/`, `e2e/fixtures`, `Cargo.lock`, the justfile or `.github/`, runs them all) and only the browser specs its files can affect, by the first matching rule of `scripts/ci/spec-map.json` and in the tier that owns each spec (`e2e/tiers.json`: UI and integration, each its own job after one shared `build` job, and a tier with no chosen spec does not run, so editor code starts no Postgres; the E2E tier never runs in presubmit, only in postsubmit, which packs the archive; `crates/cityloom_server/**` and `crates/cityloom_editor/src/sync/**` run integration, `crates/citymodel_builder/**` every spec, since it packs the archive and makes the fixtures' tiles; a new spec goes in exactly one tier or `just test-scripts` and the Playwright config fail) (a page's own files in `web/` (`map.js`, `account.css`, `street.html`...) run that page's specs and the cross-page ones; shared code, what every page loads (`app.css`, `boot.js`, `city.js`), `e2e/` helpers, the server, the build, the CI workflows and any file no rule names run every spec; a bare version bump is not a change to `Cargo.toml`); postsubmit has no `changes` job: it always runs every spec and every job before the deploy, with the UI tier in six Playwright shards and the host tests, the wasm check and the script tests as three jobs. A new spec goes in a group of that file and a new source folder gets a rule, or `just test-scripts` fails. A change made only of documentation and CI configuration (`.github/**`, `scripts/ci/**`, `scripts/include/**`, `.claude/**`: `CI_CONFIGURATION` in `ci_changes.py`) needs no version bump (the `version` output skips the Version bump job) but still runs the tests its files select (`.github/**` runs every crate). SonarCloud ignores documentation-only changes; presubmit's `CI` job (the one check to require) fails on a failed or cancelled job and passes a skipped one; postsubmit's `All checks` job does the same for the deploy. The unit-test and integration jobs of both run a Postgres service; deploy (Railway) is postsubmit's last job, on push to main only. The documentation has its own workflow, `.github/workflows/docs.yml`: it checks `website/` with Prettier and builds it (what `just docs-build` runs, without just) on a pull request or push that changes `website/**` or the workflow, and publishes it to GitHub Pages from main, without waiting for presubmit or postsubmit. The `CI` check does not cover the documentation: a broken docs build shows only in that workflow's Documentation check. No clippy configuration. `build.sh` strips the wasm's name and producers sections (~2 MB instead of ~7.6 MB). The `proc-macro-error2` future-incompat warning (from Leptos dependencies) is harmless.

Issues: labels (families `A-` area, `C-` category, `O-` browser, `P-` priority, `S-` status, plus `needs-triage`; names `<prefix>-<english> · <français>`, descriptions `<Family>: … / <Famille> : …`) live in `.github/labels.yml`, synced on push to main; the sync deletes a label not listed, so a label an automation applies must be in the file. Issue forms (`.github/ISSUE_TEMPLATE`) apply their `C-` label and `needs-triage`; `.github/issue-labeler.yml` turns dropdown answers into `A-`/`O-` labels; the maintainer sets `P-` and `S-`. `scripts/include/tests/test_issue_system.py` fails when the three disagree.

## Architecture

Vertical slices, one folder per feature, MVVM inside each:

- `street/`, `junction/` and `map/` keep each layer in its own folder; only `mod.rs` (the entry points), `i18n/` and `CLAUDE.md` stay at the slice's root (`layout_guard.rs` fails otherwise). `model/` holds the editing rules and pure computation over the domain, with no Leptos and no wording (street, junction: no DOM, signals or I/O; edits return `bool`, a refusal carries a reason); `vm/` the view-model (`vm/mod.rs`) and what it owns: in street and junction `text.rs` (words for a screen reader), the key state machines (`keys.rs`) and the `Copy` handle the views take (`watch.rs`); in map the sub-view-models (`areas.rs`, `selection.rs`), `camera.rs`, the report (`report.rs`, `report_review.rs`) and what it builds for the map port (`overlay.rs`, `style.rs`); `view/` the Leptos views, every pure SVG renderer and the component tests (`view/tests.rs`). `junction/model/` also has `geometry.rs`, `read_model.rs`, `stops.rs` and `signal.rs` (a signal's phases, one per street with entering lanes, each with a ready-made `Pattern` from `Junction::set_phase_pattern`, offered only where the lanes support it); `junction/view/` has `frame.rs`, `drawing.rs`, `iso/` (2.5D) and `iso_marks.rs`. `shell/` keeps its `vm.rs`, Leptos views and `tests.rs` side by side.
- `share/` shares a project by a link (#221): the share format, `share.html` (making a project's links; opening one into a copy, `project::copies`, never synced, shown read-only), the `ShareApi` port to `/api/share`.
- `project/` holds the projects: a project is a named container tied to an area (`model.rs`), the list in browser storage (`store.rs`, `cityloom-projects`), the move of the work from before projects into the first project (`migrate.rs`), which project a page is opened in (`context.rs`), and the home page's list (`vm.rs`, `view.rs`, `text.rs`). Each project keeps its documents under `<key>@<id>` (`shared::scoped`); the sync carries every project, the first one under bare keys.
- **What OpenStreetMap can say of a street is `cityloom_model`:** the catalogue of pieces (`cityloom_model::catalogue`, re-exported by `shared::catalogue`, which adds the regions, the add menu's groups and the message keys), the street's data (`cityloom_model::street`: `Street`, `Segment`, `Zone`, `Speed`, the curbside uses, stops, raised elements and green, with their serde form and the methods that only read or rearrange them; re-exported by `street::model`) and the reading of a road's lanes as pieces (`cityloom_model::street::{class_of, pieces, legacy_pieces, one_way_bike_lanes, refs}`, in `cityloom_model/src/street/from_road.rs`, used by `city::import`); a street's or junction's OSM source is `cityloom_model::SourceRef` (the editor's `shared::provenance::OsmRef`). The editing rules, checks, thresholds, message keys and anything that reads the standards profile stay in the editor, on extension traits of those types (`street::model::{StreetExt, UseExt, StopKindExt, CalmingKindExt, CalmingExt, GreenKindExt, GreenExt, TreeSizeExt}`); bring the trait into scope to call them.
- **Dependency rule:** a slice may use another slice's `model` (junction uses the street model; city uses both; `sync::local` uses `project::model`), `city::store` / `city::binding` / `city::projection`, `city::edits` (project, sync), `restriction::store`, `standards::model` / `standards::store` (street), `place::area`, `project::copies` (share: the copy of a shared design; the shell: `copies::{is_copy, fork}`, making a copy one of the person's projects, #223), `project::context` (which project a page is opened in: map, street, junction, place, archive, and `city::store` for the area a project's record names; the shell, for whether the page shows it read-only, `context::read_only`) and `shared`; never another slice's `vm`, views or text (in `street/`, `junction/` and `map/`: only what is under `model/`, except the report's figures, `street::view::drawing` and `junction::view::figure`, which `map/vm/report.rs` draws; and a shell test builds a `street::vm::StreetVm`). `project::store` and `project::migrate::{legacy_waiting, legacy_kept, area_moved}` are used by `sync::local` (every project's records and the projects' own; the places wait while work from before projects waits to be moved); `project::store` itself uses `city::edits`, `city::store` and `restriction::store` (a project's records, and blanking them on delete). Stores and editors (`city/`, `restriction/`, `project/`, `street/`, `junction/`) also use `sync::model` (`Id`, `Kind`, `Change`, `Origin`, `Report`, `mark`), which depends only on `shared`; the shell builds `sync::SyncVm`; every other slice reaches the sync only through `sync::hub` and `sync::model`. `shared` depends on no slice. A page made of several slices is put together in `lib.rs`, the composition root: the home page is `project::mount_list` alone (handed the share slice's `share::links::ProjectShares` as its `project::model::ProjectLinks`, so a project's share links end before it does), and the About page is `project::migrate::move_legacy_work` and then `map::mount_about`, so `project` uses no other slice's page. A page in no project that syncs (the home page, the About page, `account::mount_account`) first runs `project::migrate::move_legacy_work`. New code goes in the slice that owns the feature, not in a layer folder.
- **View-models** expose presentation-ready reactive getters and take commands. They reach the browser only through the ports, so they are tested natively against `test_ports()` / `test_ports_with_time()`.
- **Views** bind to a view-model and forward events; they decide nothing. Rendering is by pure functions returning SVG strings (`junction/view/iso/`, `street/view/iso/`, `map/view/svg.rs` for the About page's city only) set with `inner_html`; pointer and keyboard logic are pure state machines with tests. `shell/view.rs` binds the shared static markup to `ShellVm`. `map/` draws with MapLibre, no SVG.
- **Entry points** are in each slice's `mod.rs` (wasm-bindgen exports: `Editor`/`open_junction`/`mount_page`, `Sheet`/`open_street`/`mount_street_page`, `mount_map(canvas)`) and `lib.rs` (`mount_projects`, the home page, which `web/home.js` calls; `mount_about`, the About page, which `web/about.js` calls before `prepare_city` and `.mount_city()`; `mount_compare`, the comparison page, which `web/compare.js` calls and which hands the street or junction slice its half through `mount_compare_street` / `mount_compare_junction`). Each opens inside the page's project (`project::context::open_page`: `?project=<id>`, else the one opened last; none here sends the page to `index.html?missing=1` and gives nothing); links to `map.html`, `street.html`, `intersection.html` carry `project=<id>` (`shared::project_id::link`; the shell rewrites the markup's). `&view=1` opens the project read-only (#222; `Storage::read_only`, every view-model's `read_only()`, the shell's top-bar tag; the links keep it). A page script (`web/app.js`, `junction.js`, `map.js`) only loads the module, sets up the hatch `<defs>` (not `map.js`, which passes `createMapCanvas` from `web/mapcanvas.js` to `mount_map`) and calls `mount_*` and `.mount_shell()`.

Translation: English and fr-CA on every app page (all but `credits.html`) and the shell.

- Engine `shared/i18n.rs` (`I18n` with `tr`/`tr_now`, `detect`, `LANG_KEY`, ...). Slices owning messages (shell, account, street, city, map, place, junction, restriction, sync, archive, project, timeline, share) have `i18n/{en,fr}.ftl` and a `RESOURCES` const, registered only in `lib.rs::i18n_for`. Text functions take `&I18n`; views use the tracked `tr`/`say` so they follow a switch, commands use `tr_now`/`say_now`.
- The model never holds wording: it says things as `Said` data (`shared/said.rs`: a key and `Arg`s) that `say` renders in the current language. Names the app invents (place, street title, ends, class words, "unnamed") are `Said` too, with messages in `city/i18n`.
- Message keys are global: a slice words another slice's messages only by key through `Said`/`Arg`, never by importing its text.
- The shell owns the switch (`ShellVm::set_locale` keeps `cityloom-lang`, sets `<html lang>`); page markup carries `data-i18n*` attributes filled by `shell/view.rs::apply_translations`. `web/junction.js` holds no wording (`mount_bare_shell`).

## Conventions and gotchas

- Test-driven: write the failing test first. Commit each change separately once the tests pass.
- Logic belongs in Rust; JS in `web/` is start-up glue only. The exception is `web/mapcanvas.js`, the adapter owning the MapLibre map (vendored MapLibre in `web/vendor`).
- Adding a string: add it to both `.ftl` files with the same id and variables (a parity test fails otherwise). Whole sentences with named placeables, never concatenated pieces; plurals use selectors (`[one]` / `*[other]`). Write an ordinary space before `:` in the `.ftl`. fr-CA follows the OQLF: no-break space before `:` and inside `« »`, none before `;` `!` `?`. Terms: `docs/glossary-fr-ca.md`. Lengths and typed numbers go through `Units::*_in(…, locale)` and `parse_number`, never `format!("{:.1}")`.
- `src/i18n_guard.rs` fails on any wording in the files listed in `MIGRATED` (add a file when its slice migrates; `LEFT_OUT` names the few left out; a file of a translated slice (account, archive, map, place, junction, city, restriction, sync, project) in neither list fails). A literal that only looks like a word goes in `ALLOWED_LITERALS`, a kebab-case literal that is not a message (an element id, a CSS class) in `NOT_MESSAGE_IDS`, each with its reason; any other kebab-case literal must be a message in both languages, and a dead entry fails.
- Still English: `web/credits.html`, OSM data, MapLibre's strings.
- Accessibility (WCAG 2.2 AA): `shared/contrast.rs` (tests only) measures the colour tokens of `web/app.css` and `editor.css`; a new colour pair for text or a control goes there. `shell/header.rs` keeps `--bar-stuck` and `html` has that much `scroll-padding-top`, so focus is never hidden under the sticky bar. Editors open with a skip link to `#wrap`; an `h2` heads the details panel.
- View-model behaviour gets a native test against the port fakes. Component tests render to HTML on the host (each slice's `tests.rs`, helpers in `shared/testing.rs`); `shared::platform::browser_ports()` also works natively.
- Non-`Send` values inside reactive closures go in `StoredValue::new_local`; views take a `Copy` handle (`junction::vm::watch::Watch`, `street::vm::watch::SheetWatch`) over an `Rc<…Vm>`.
- `any_spawner::Executor::init_wasm_bindgen()` must run at the top of every `mount_*` function before any component creates an effect.
- `#![recursion_limit = "1024"]` is needed for the Leptos `view!` macros. New web-sys APIs need their feature added in `Cargo.toml`.
- Versioning: `version` in `crates/cityloom_editor/Cargo.toml` (semver) is the product's version, shown in the app pages' footer. Every pull request raises it (major: breaking, minor: feature, patch: fix), except one made only of documentation and CI configuration (see CI above), and runs `cargo update -p cityloom_editor` for `Cargo.lock`; presubmit's `version` job (`scripts/check-version.sh`) fails the PR otherwise.
- Merging and deploying: `.claude/agents/deploy.md` (Haiku) merges the PRs it is told to, one at a time, by a fixed runbook (rebase on the version line only, tests, CI, a `CLEAN` merge, deploy, live site) and stops on anything needing judgment (another conflict, a failing or pending check, a failed deploy), handing it back to the session that sent it. `.claude/agents/merge.md` (Opus) prepares PRs for it and never merges: by the same runbook up to the CI wait, it brings each PR up to date and fixes what stands in the way: failing CI checks and every SonarCloud issue the PR brings in (read from SonarCloud's API for the PR's head commit), as separate commits on the PR's branch, at most three rounds, never by silencing a finding or touching what decides a check (`.github/`, `scripts/`, `sonar-project.properties`, the guards); a rebase conflict beyond the version line, a hotspot, a flaky test, a failed Sonar API call or a finding outside the PR still stops it. It hands back each PR green and `CLEAN`, for the deploy agent once the user says to merge.
- Software factory (CLM-18, `.claude/factory/README.md`): `/factory` runs one pass of a line of agents that takes a Linear issue (team Cityloom, moved by a person to Todo) to a deployed change: `factory-queue`, `factory-triage` (`triage` agent), `factory-plan` (`planner`, posts the plan on the issue, makes the worktree), `factory-build` (`test-writer`, then `implement`), `factory-review` (`reviewer`), `factory-evidence` (`evidence-check`, opens the PR as the GitHub App, then `merge`), and after a person approves the PR's head, `deploy`. It keeps no state: each pass reads Linear's states, labels and `**Factory · …**` comments, the worktree `../worktrees/clm-<n>`, and GitHub. A person decides only an issue handed back (`S-needs-review` / `S-needs-setup`) and the approval. Tests come first and only the test-writer writes them: `gate.py red` passes the red commit when its new tests compile, every one fails and every old one passes; the `implement` agent may not change a test (`guard.py`, the PreToolUse hook of `.claude/settings.json`, refuses it, and a test it believes wrong is a dispute for a person); `gate.py green` passes when every test passes with warnings denied, formatting and the version hold, and no test file, `#[cfg(test)]` block, check or factory file changed since the red commit. The red commit stays local to the worktree and the branch is pushed only once green, since CI denies warnings and the `todo!()` stubs cannot pass it; the PR shows red then green as its failing-then-passing evidence. An issue that asks only for documentation takes the docs flow instead (CLM-47; triage says which, in its record's `Flow:` line): the `writer` agent writes the pages in both languages from a plan of facts, each tied to the code, and `gate.py docs` passes the head when it changes only documentation, every page of the site has its other language's, and the site passes the Documentation workflow's Prettier check and builds; the reviewer holds each fact against the code and the evidence is the built pages in English and fr-CA.
- Real-browser checks: a background tab throttles timers to ~1 s, pauses `requestAnimationFrame` and ignores `.focus()`, so use microtask waits and expect focus behaviour to be unverifiable. After rebuilding, bust the cache with `fetch(url, {cache: 'reload'})` for the wasm, glue JS and page script, then reload.

- `src/street/CLAUDE.md`: Street slice (`src/street/`)
- `src/junction/CLAUDE.md`: Junction slice (`src/junction/`)
