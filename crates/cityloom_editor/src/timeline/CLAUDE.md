# Timeline slice (`src/timeline/`)

Loaded when working in this folder; the root `CLAUDE.md` has the project-wide rules.

Design timeline (#73): named milestones of a project's work, to look at, compare with the present and put back.

- `model.rs` (no I/O, no wording): `Milestone` (the header the timeline lists: `id`, `name`, `created_at` as a sync stamp, `auto` for one the app made before a restore, `app_version`, `author` when someone was signed in, `Summary { streets, junctions, rules }`), `Snapshot { edits, restrictions }` (the `cityloom-edits` and `cityloom-restrictions` documents as the stores keep them, the archive's shape), `Draft` (what a new one is made of), `Refused { Empty, TooLong, TooLarge, Unknown, Unusable }` (data only), `clean_name` (trimmed, 1-80 characters). `MAX_BYTES` (1 MiB) is what the server takes of one record (`cityloom_server::work::MAX_RECORD_BYTES`); a snapshot over it is refused (`TooLarge`), never cut.
- `store.rs`: `MilestoneStore` over `cityloom-milestones` (`{"version":1,"milestones":{<id>: record}}`, scoped: `cityloom-milestones@<project>`). **Takes a project's storage, never the root.** Records are kept as JSON, so what a newer build adds survives a rename. `list` is oldest first, header only (the snapshot is read by `snapshot(id)`). `create`, `rename`, `delete` mark `Kind::Milestone` for the sync (key = the bare id, which travels as `<project>:<id>` outside `first`). Ids `m-` + 12 hex digits where storage has randomness, else `m<n>` past the highest the document or the sync document has held, so a deleted milestone's id stays dead. A newer build's document is neither read nor written; a damaged one is copied to `cityloom-milestones-damaged` once, before the first write. The sync's own writes (`raw_ids`, `raw`, `put_raw`, `remove_raw`) never mark and need `is_usable()` first.
- `work.rs` (no wording): a project's work as raw JSON records by `(Kind, key)` (`Records`, `records_of`, `summary_of`). `capture(storage)` reads the project's `cityloom-edits` and `cityloom-restrictions` documents into a `Snapshot` (refused, `Unusable`, where one is damaged or a newer build's). `compare(milestone, now)` gives each place made since (`Added`), gone (`Removed`) or different (`Changed`), by record equality, in kind and key order. `restore(storage, id, backup_name, app_version, author)` first keeps the work it would replace as an `auto` milestone named `backup_name` (the caller words it), then puts every differing record back through `Draft::put_raw`/`remove_raw` and `RestrictionStore::put_raw`/`remove_raw` and marks them for the sync (put back = written, made since = removed); the backup refused (`TooLarge`) or a write refused changes nothing (both documents are put as they were and the backup dropped); work already as the milestone had it changes and keeps nothing. Restoring the backup undoes a restore. An editor open on the project is not told: the page that restores reloads it.
- Sync: `sync::model::Kind::Milestone` (not a place: `is_place` is false, so it is not counted in the merge report); `sync::local` reads, writes, lists and removes it like a rule; a damaged milestones document pauses milestones alone. `project::store::records` lists a project's milestones, so deleting the project tombstones them. Server: migration `0004_work_milestone_kind.sql`; a record may be 1 MiB and an account holds 16 MiB sealed.
- Not exported by the archive (`archive/`): a milestone is history, not work.
- May use `shared`, `sync::model`, `city::edits` and `restriction::store` (the stores a snapshot is read from and restored to); never another slice's `vm`, views or text. `sync::local` and `project::store` use `timeline::store`.
