# Project slice (`src/project/`)

Loaded when working in this folder; the root `CLAUDE.md` has the project-wide rules.

- A project is a named container tied to a metropolitan area, chosen when it is made and fixed then. `model.rs`: `Project { id, name, area (Area::to_query: the place in the metropolitan area its map opens on; the metropolitan area is `place::area::metro_of` it), created_at (sync stamp), placeholder (omitted when false) }`, `Refused { Empty, TooLong, Unknown, Unusable }` (data only: no wording here, the words come later as `Said`), names trimmed, 1-80 characters.
- `store.rs`: `ProjectStore` over `cityloom-projects` (`{"version":1,"projects":[…]}`, creation order). Future version left alone; damaged copied to `cityloom-projects-damaged` only by the next successful change; each write re-reads. `cityloom-project` holds the last-opened id. Each change marks `Kind::Project` (key = the project id) for the sync. `create_in(name, &Metro)` keeps `metro.start()`; `create(name)` is `create_in` the default metro.
- **`ProjectStore::new` takes the ROOT storage, never a `ScopedStorage`**: the list and the last-opened id belong to no project, and `mark` would otherwise prefix the key.
- `delete` removes the record, blanks the project's scoped keys (`shared::scoped::SCOPED_KEYS`, each as `<key>@<id>`; `Storage` has no removal, an empty value reads as absent) and marks deleted (one `sync::model::mark_all`, wire keys) the project record and every record of the project: what `records` finds in its documents, read before they are blanked, and the live entries of the sync document whose wire key belongs to it.
- A damaged list is copied aside only once a change is taken (a refused `rename`/`delete` copies nothing).
- `records(root, project)`: the project's streets, junctions, rules, milestones and area as `(Kind, key)` with bare keys, from its scoped documents (none from an unusable one), without a key that does not `round_trips` (a `p-abc:w1` in `first` is `p-abc`'s: neither sent nor tombstoned by `delete("first")`). `sync::local::ids` builds on it. Uses `city::edits`, `city::store::AREA_KEY`, `restriction::store`, `timeline::store`.
- The sync's own writes, never marked: `put_raw` (a pulled `project` record, in place or appended), `ensure` (a placeholder `PLACEHOLDER_NAME` "Project", data only, for a project whose places came first; `placeholder: true`, never sent; a rename makes it the person's), `remove_raw` (entry, scoped keys, last-opened id). All refuse where the list is damaged or a newer build's.
- Ids: `p-` + 12 hex digits where storage has randomness, else `p<n>` one past the highest number the list or the sync document (`project/<id>` entries, tombstones too) has ever held, so a deleted id is never reused; a random id the sync document knows is not taken either. `first` is the first project's id (`shared::project_id`).
- `last_changed` is the newest `edited_at` among the sync entries of a project (its `project/<id>` entry and records whose wire key belongs to it), else `created_at`.
- `migrate.rs`: `migrate_legacy(storage, first_name) -> bool` moves the work from before projects (bare `cityloom-edits`, `-edits-damaged`, `-restrictions`, `-restrictions-damaged`, `-area`) into project `first` (name passed in, wording is the caller's; `created_at` `stamp(0)`, so devices migrating apart make the same record). Runs only where `legacy_waiting`: the list is usable and holds no project but `first` (none; a placeholder `first`, adopted: made real with this name; or a real `first` a sync brought from a device that moved its work first, whose record is kept as it is), and a legacy edits or restrictions key is non-blank (an area alone starts nothing). While `legacy_waiting`, `sync::local::usable` is false for every place kind (street, junction, rule, area): pending legacy entries name bare keys, now `first`'s, and would otherwise go up as removals read from `first`'s still empty documents; the sync pauses (and says so) until the move. Should the move fail and the pause lift (another project listed), the sync still sends nothing for a pending first-project record the bare legacy document holds and `first`'s does not (`sync::local::legacy_hold`, only while `legacy_kept`: a legacy edits or restrictions key is kept; the area only where `area_moved`, Montreal): it stays pending, never a removal. Area: the stored one if it parses and `place::area::is_montreal`, else `default_area()`; an area not used is neither moved nor blanked; a non-blank `cityloom-area@first` is not written over, though it decides nothing: the pages open the area the project's record names (`context::area_of`), the legacy one where the migration makes the record. Order: put every document in place under `<key>@first` and read it back (a refused or mismatching write is undone and returns false, nothing listed, nothing blanked, the next launch retries); then list the project; then blank the old keys. Where `<key>@first` already holds something different (the sync pulled rows into a placeholder `first` first): edits and rules are merged record by record through the raw APIs (`Draft`, `RestrictionStore::raw/put_raw`, so unknown fields pass): a legacy record is added where absent, and replaces a pulled one only where the root sync document holds a PENDING entry for that bare wire key, else the pulled one stands. A document that cannot be read (damaged or a newer build's, either side) is never written over: nothing changes, the project stays unlisted and false is returned. A salvage (`-damaged`) copy already there stands, the old one stays, false. **The sync document is not touched for moved records**: first-project wire keys are bare, so existing entries (synced, pending) stay as they are and records with no entry are claimed by the sync (`claim_unmarked`) with their own time; re-marking them would stamp stale copies with now and beat newer edits made elsewhere. Only the project's own record gets an entry, `sync::model::claim_at(Project, first, stamp(0))`, when it has none (a rename or pulled record always wins). A legacy record whose key does not `round_trips` in `first` (an older build's tab kept a pulled `p-abc:w1` there) is dropped, in a plain move and a merge alike: it is that project's, on the server. True means everything found was moved and blanked.
- `copies.rs` (#221): the copies of shared designs this browser opened, each a project of its own (documents under `<key>@<id>`, ids `s-<hex>`/`s<n>`, never a project's own) listed apart in `cityloom-shared-copies` (`{"version":1,"copies":[{id, token, name, area, opened_at}]}`, a `DESIGN_KEYS` key). Only the pages' lookup `context::find` (listed or copy: `resolve`, the guarded storage, `area_of`, `leave_when_removed`, `lib.rs`) knows them; the person's list does not (`store::find`, `ProjectStore::{list, get, ensure, open, last_opened, remove_raw}`), so the home page, the sync (`sync::local::{projects, ids}`), the move from before projects and the project opened last never see one. `keep(root, token, name, area, documents)` writes the documents (blanked first) and lists the copy, never marking; the same token replaces its copy under the same id; the oldest go, documents and all, past `MAX_COPIES` (10) or `MAX_COPIES_BYTES` (2 MiB of documents together, the new copy counted first and always kept), before anything is written; where the browser still refuses a write (its storage is full: the person's own work is there too) the oldest copy left goes and the write is tried again, until no other copy is left; then the copy is not kept (`Unusable`): what it wrote is blanked and it is not listed (copies dropped to make room stay dropped: each can be opened again from its link). `context` opens a copy only to read whatever the address says (`is_copy`), and `ProjectStore::open` refuses to remember it as the project opened last. A damaged or newer list holds no copy (each can be opened again from its link).
- `context.rs`: which project a page is opened in. `find(storage, id)`: the project a page may open, listed (`store::find`) or a copy of a shared design (`copies::find`). `resolve(root, search) -> Resolved { Project(id), Missing }`: the project `?project=` names (`find`); a `project=` naming none listed (or empty) is `Missing`, never the last-opened one; no `project=`: `last_opened` (still listed), else `Missing`. The search comes from `Ports::page.path()` (no page script passes it). `enter(ports)`: the page's ports scoped to the project (`ScopedStorage::guarded`, asking `find` over the root before each write: once another tab deleted the project, no sync needed, the page writes and marks nothing, so an editor still open cannot bring it back; `peek` gives the same guarded storage) and the project remembered as last opened, or on `Missing` `Navigator::replace(MISSING_HREF)` (`index.html?missing=1`) and none, with nothing read or written of the project. `open_page` = `enter` + `leave_when_removed(root, &Rc<ScopedStorage>)` (a `hub::register` listener, registered before the editor's own: a sync `Change` of `project/<id>` with the project no longer listed `close`s the page's `ScopedStorage`, so no later flush writes or marks the gone project, and sends the page to `MISSING_HREF`); each page registers it once (`mount_map`, `open_street_in`, `open_junction_in`; `enter_junction_in` and `mount_bare_shell` use `enter`). `peek(ports) -> Option<Ports>`: the project's ports, no navigation or memory; `None` where nothing resolves, and writers then stay inert (`ArchiveVm::for_page` does nothing) rather than write the root storage; only readers fall back to root (`prepare_city`, the About page's city). Read-only (#222): where the address holds `view=1` (`shared::project_id::viewing`), `enter`, `open_page` and `peek` give the project's storage `only_to_read` (every write of the design, the list of projects and every mark refused, the person's caches and preferences such as an area's roads and the goal still kept; `Storage::read_only` true); `read_only(storage, id, search)` is the one question, asked by `page_storage` and the shell's top bar (`ShellVm::read_only`): `view=1`, or the project is a copy of a shared design; it is the one switch the view-models read (`read_only()`), and the share link (#221) is to set it. It is not on the `Project` record (that would sync), the project is still remembered as opened last, and no page removes `view=1` (`project_id::link_in` keeps it on the links between a project's pages). `area_of(storage)`: the area the record of `storage`'s project (`Storage::project`) names, read through `find` (any storage: a `ScopedStorage` passes `cityloom-projects` to the root); `None` over the root storage, for a project not listed, a placeholder or an area that does not parse. `city::store::CityStore::current_area` reads it first, so a project opens the area its record names.
- The home page is the list (`vm.rs`, `view.rs`, `text.rs`, `i18n/`): `ProjectsVm::new(root ports, i18n)` first runs `migrate::move_legacy_work(root, i18n)`: `migrate_legacy` with the translated `project-first-name` and, where that took the work into `first` (made it, or a real one took it) and nothing was opened before, opens it (`LAST_KEY`) so the pages open the old work as before; it says whether it moved the work now. The Account page's `mount_account` calls it too, before it builds anything (its shell syncs as soon as it knows who is signed in, and a sign-in comes back there). `rows()` (`Row { id, name, area_label, changed }`) is newest `last_changed` first; `area_label` is the name of the metropolitan area holding the record's area (any build's record: the Plateau or another Montréal place is "Montréal"), a place no metro holds by its own name, an area that does not parse by the default metro (it opens the default area); a placeholder's `name` is the page's language's, not its data (`project-first-name` for `first`, as the migration names it: an older CityLoom's bare-key rows on a clean device land there; else `project-placeholder-name`), and the delete announcement uses the same; `changed` is `text::changed_text` (`project-changed` with `project-date`: `November 12, 2026` / `12 novembre 2026`, `1er` for the first; UTC day; empty for an unreadable stamp or the epoch, which says only that the time is not known). The create form: the name field and a labelled `<select>` (`#project-metro-field`, `project-metro`, described by `#project-metro-hint`, `project-metro-fixed`) of `metro_options()` (`MetroOption { id, label, chosen }`, every catalogue entry, the default chosen); `choose_metro(id)` (false for an id the catalogue lacks) and `create` makes the project in the chosen one. The row shows it under `project-metro`, read-only: neither the row nor the rename form can change it. The row also links to the project's timeline (`timeline_href`) and to the page that shares it (`share_href`, `share.html?project=<id>`, `project-share`, #221). Commands: `create`, `start_rename`/`rename`/`cancel_rename`, `ask_delete`/`confirm_delete`/`cancel_delete` (asked in the row, Escape cancels; where the project has share links made on this device that still work, `model::ProjectLinks` (#221, `ProjectsVm::new_with`, the share slice's `share::links::ProjectShares` handed in by `lib.rs`; `NoLinks` otherwise), the question says they stop working too (`project-delete-confirm-links`), and confirming deletes them on the server first (`ending()`: both answers wait, `aria-disabled`, focus kept); the project goes once none is left, else it is kept and the question shows and announces why (`delete_error`, `project-delete-links-failed` with the share slice's reason, in `project-delete-anyway-offer`), to try again, cancel, or delete it anyway (`can_delete_anyway`/`delete_anyway`, `#project-delete-anyway`: its links then keep working until they expire), so links that cannot be ended from here (the account deleted, another signed in, no server) never keep a project for good), `open` (`store.open`, then `Navigator::go("map.html?project=<id>")`; the row's link has that `href`, and a modified click is the browser's). Refusals are `text::refused_key` messages beside the field (`aria-invalid`); each change is announced; focus is asked for through `focus_request` (`Focus`). `notice()` is `project-gone` for `?missing=1` (unless `move_legacy_work` just moved the work: a bookmark from before projects named no project and was sent here, and its project is here now) until the first command (`create`, `rename`, `confirm_delete`, `open`); one `role="status"` paragraph for the page's life, `hidden` when empty, so it is never a new node. A refused name is also announced (Enter leaves focus in the field). The rename form is named `project-rename-named`. A `hub::register` listener and a `storage` listener (`mount_list`: `PROJECTS_KEY`, `SYNC_KEY`) redraw the list. Each `li` is named by `aria-labelledby` of its name and area. `index.html` holds the skip link (`project-skip`, to `#projects-heading`), the shared top bar (Projects current) and `#projects-slot`, nothing else: no city is read there (About CityLoom is `about.html`, the map slice's). `ProjectsView` sets the window title, `project-page-title`, in the page's language.
- `mount_list(root ports, i18n, links)` builds the `ProjectsVm` (so the migration runs first), draws it into `#projects-slot` and redraws on a `storage` event. The home page is put together in `lib.rs` (the composition root, where slices may meet): wasm `mount_projects()` makes one `I18n`, calls `project::mount_list` (with `share::links::ProjectShares` over the root ports) and returns `HomePage` (`mount_shell`, the shell over a `shell::Bare` target). The About page is put together there too: `mount_about()` runs `migrate::move_legacy_work` (its shell syncs) and then `map::mount_about`. The project slice uses no other slice's page (a test reads its sources).
- May use `shared`, `sync::model`, `sync::hub`, `place::area`, `city::edits`, `city::store`, `restriction::store`; never another slice's `vm`, views or text. `sync::local` uses `project::store` and `project::migrate::{legacy_waiting, legacy_kept, area_moved}`; map, street, junction, place, city (`CityStore::current_area`) and the shell use `project::context`.
