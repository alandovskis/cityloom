# Project slice (`src/project/`)

Loaded when working in this folder; the root `CLAUDE.md` has the project-wide rules.

- A project is a named container tied to an area. `model.rs`: `Project { id, name, area (Area::to_query), created_at (sync stamp), placeholder (omitted when false) }`, `Refused { Empty, TooLong, Unknown, Unusable }` (data only: no wording here, the words come later as `Said`), names trimmed, 1-80 characters.
- `store.rs`: `ProjectStore` over `cityloom-projects` (`{"version":1,"projects":[…]}`, creation order). Future version left alone; damaged copied to `cityloom-projects-damaged` only by the next successful change; each write re-reads. `cityloom-project` holds the last-opened id. Each change marks `Kind::Project` (key = the project id) for the sync.
- **`ProjectStore::new` takes the ROOT storage, never a `ScopedStorage`**: the list and the last-opened id belong to no project, and `mark` would otherwise prefix the key.
- `delete` removes the record, blanks the project's scoped keys (`shared::scoped::SCOPED_KEYS`, each as `<key>@<id>`; `Storage` has no removal, an empty value reads as absent) and marks deleted (one `sync::model::mark_all`, wire keys) the project record and every record of the project: what `records` finds in its documents, read before they are blanked, and the live entries of the sync document whose wire key belongs to it.
- A damaged list is copied aside only once a change is taken (a refused `rename`/`delete` copies nothing).
- `records(root, project)`: the project's streets, junctions, rules and area as `(Kind, key)` with bare keys, from its scoped documents (none from an unusable one). `sync::local::ids` builds on it. Uses `city::edits`, `city::store::AREA_KEY`, `restriction::store`.
- The sync's own writes, never marked: `put_raw` (a pulled `project` record, in place or appended), `ensure` (a placeholder `PLACEHOLDER_NAME` "Project", data only, for a project whose places came first; `placeholder: true`, never sent; a rename makes it the person's), `remove_raw` (entry, scoped keys, last-opened id). All refuse where the list is damaged or a newer build's.
- Ids: `p-` + 12 hex digits where storage has randomness, else `p<n>` one past the highest number the list or the sync document (`project/<id>` entries, tombstones too) has ever held, so a deleted id is never reused; a random id the sync document knows is not taken either. `first` is the first project's id (`shared::project_id`).
- `last_changed` is the newest `edited_at` among the sync entries of a project (its `project/<id>` entry and records whose wire key belongs to it), else `created_at`.
- `migrate.rs`: `migrate_legacy(storage, first_name) -> bool` moves the work from before projects (bare `cityloom-edits`, `-edits-damaged`, `-restrictions`, `-restrictions-damaged`, `-area`) into project `first` (name passed in, wording is the caller's; `created_at` `stamp(0)`, so devices migrating apart make the same record). Runs only where the list is usable and empty, or holds just a placeholder `first` (adopted: made real); a legacy edits or restrictions key must be non-blank (an area alone starts nothing). Area: the stored one if it parses and `place::area::is_montreal`, else `default_area()`; an area not used is neither moved nor blanked; a non-blank `cityloom-area@first` stands over the legacy one. Order: put every document in place under `<key>@first` and read it back (a refused or mismatching write is undone and returns false, nothing listed, nothing blanked, the next launch retries); then list the project; then blank the old keys. Where `<key>@first` already holds something different (the sync pulled rows into a placeholder `first` first): edits and rules are merged record by record through the raw APIs (`Draft`, `RestrictionStore::raw/put_raw`, so unknown fields pass): a legacy record is added where absent, and replaces a pulled one only where the root sync document holds a PENDING entry for that bare wire key, else the pulled one stands. A document that cannot be read (damaged or a newer build's, either side) is never written over: nothing changes, the project stays unlisted and false is returned. A salvage (`-damaged`) copy already there stands, the old one stays, false. **The sync document is not touched for moved records**: first-project wire keys are bare, so existing entries (synced, pending) stay as they are and records with no entry are claimed by the sync (`claim_unmarked`) with their own time; re-marking them would stamp stale copies with now and beat newer edits made elsewhere. Only the project's own record gets an entry, `sync::model::claim_at(Project, first, stamp(0))`, when it has none (a rename or pulled record always wins). True means everything found was moved and blanked.
- `context.rs`: which project a page is opened in. `resolve(root, search) -> Resolved { Project(id), Missing }`: the listed project `?project=` names; a `project=` naming none listed (or empty) is `Missing`, never the last-opened one; no `project=`: `last_opened` (still listed), else `Missing`. The search comes from `Ports::page.path()` (no page script passes it). `enter(ports)`: the page's ports scoped to the project (`shared::scoped::in_project`) and the project remembered as last opened, or on `Missing` `Navigator::replace(MISSING_HREF)` (`index.html?missing=1`) and none, with nothing read or written of the project. `open_page` = `enter` + `leave_when_removed(root, &Rc<ScopedStorage>)` (a `hub::register` listener, registered before the editor's own: a sync `Change` of `project/<id>` with the project no longer listed `close`s the page's `ScopedStorage`, so no later flush writes or marks the gone project, and sends the page to `MISSING_HREF`); each page registers it once (`mount_map`, `open_street_in`, `open_junction_in`; `enter_junction_in` and `mount_bare_shell` use `enter`). `peek(ports) -> Option<Ports>`: the project's ports, no navigation or memory; `None` where nothing resolves, and writers then stay inert (`ArchiveVm::for_page`, `AreaVm::for_page` do nothing) rather than write the root storage; only readers fall back to root (`prepare_city`, the home page's city).
- The home page is the list (`vm.rs`, `view.rs`, `text.rs`, `i18n/`): `ProjectsVm::new(root ports, i18n)` first runs `migrate_legacy` with the translated `project-first-name` and, where that listed `first` and nothing was opened before, opens it (`LAST_KEY`) so the pages open the old work as before. `rows()` (`Row { id, name, area_label, changed }`) is newest `last_changed` first; `changed` is `text::changed_text` (`project-changed` with `project-date`: `November 12, 2026` / `12 novembre 2026`, `1er` for the first; UTC day; empty for an unreadable stamp or the epoch, which says only that the time is not known). Commands: `create`, `start_rename`/`rename`/`cancel_rename`, `ask_delete`/`confirm_delete`/`cancel_delete` (asked in the row, Escape cancels), `open` (`store.open`, then `Navigator::go("map.html?project=<id>")`; the row's link has that `href`, and a modified click is the browser's). Refusals are `text::refused_key` messages beside the field (`aria-invalid`); each change is announced; focus is asked for through `focus_request` (`Focus`). `notice()` is `project-gone` for `?missing=1`, an `role="alert"` paragraph. A `hub::register` listener and a `storage` listener (`mount_list`: `PROJECTS_KEY`, `SYNC_KEY`) redraw the list. Each `li` is named by `aria-labelledby` of its name and area. `index.html` holds the skip link (`project-skip`, to `#projects-heading`), `#projects-slot` and the About section (the former hero: `project-about-heading` h2, the old h1 as `.about-title`).
- `mount_list(root ports, i18n)` builds the `ProjectsVm` (so the migration runs first), draws it into `#projects-slot` and redraws on a `storage` event. The home page is put together in `lib.rs` (the composition root, where slices may meet): wasm `mount_projects()` makes one `I18n`, calls `project::mount_list` and then `map::mount_home(i18n)` (About section: place search, window title, city), and returns `HomePage` (`mount_shell`, `mount_city`, delegated to the `map::MapPage`). The project slice uses no other slice's page (a test reads its sources).
- May use `shared`, `sync::model`, `sync::hub`, `place::area`, `city::edits`, `city::store`, `restriction::store`; never another slice's `vm`, views or text. `sync::local` uses `project::store`; map, street, junction, place and the shell use `project::context`.
