# `citymodel_builder`

Loaded when working in this folder; the root `CLAUDE.md` has the project-wide rules.

- Prepares an area's data, defines the `.citymodel` archive and holds the OpenStreetMap importer (`importer`, the former `osm_import` crate). Workspace crate, not built to wasm (the wasm build excludes it and `cityloom_server`).
- Library `archive` + `metro_index`, deps only `tar`, `sha2`, `thiserror`; the server uses it with default features off. Feature `import` adds the importer (`importer`: osm2streets and its git dependencies, `cityloom_model`); feature `cli` (default) turns on `import` and adds `ureq`, `clap`, `serde_json`, `ctrlc` for the binary. `network_tiles` is gated on `cli`, not `import`, because it needs `serde_json` and `sha2` beside the importer's types.
- **Archive**: plain ustar tar, deterministic (mtime 0, owner 0, mode 0644, fixed member order): `cityloom.idx` first, then `networks/<x>_<y>.json` (a `NetworkTile`; unpacked as `metro/<x>_<y>.json`).
- **Index**: binary; magic `CLOOMIDX`, version 2 (a version 1 archive, of OSM PBF road tiles, is refused), flags 0. Header (area name, creation time, source name + replication time, grid `lon0`, `lat0`, `dlon`, `dlat` as in `index.json` plus `nx`, `ny`), entries (kind network, `x`, `y`, size, SHA-256, path), SHA-256 trailer over all before it. Max 1 MiB; area name lower-case letters, digits, hyphens, max 64.
- `metro_index` is the one writer of `index.json` (`index_json`), for `tiles` and the server's unpack, so bytes match and keep the shape the app reads (`place/tiles.rs`). Checksums: first 16 hex digits of an entry's SHA-256 (`short_checksum`). `nx`/`ny` are in the archive, not `index.json`.
- Binary modules: `progress` (see `just prepare`: pure frame function, ANSI renderer, plain mode, logs and tails, Ctrl-C restores cursor), `download` (resumable), `tiles` (grid and the pipeline's steps), `network_tiles` (cuts the whole network along the grid, writes the JSON tiles), `prepare` (extract, tiles, archive), `commands` (`clap`).
- osmium stays external. Commands: `prepare`, `tiles` (`--out` names the tiles' folder), `pack`, `fixture <in.osm|pbf> <out.json>` (one `NetworkTile` of the input's own frame: the e2e fixtures, `just e2e-fixtures`) and `import <in.osm|pbf> <out.json>` (the whole `Network` as JSON, to look at). No `--batch`.
- The `tiles` steps: osmium filters (`area`, `highways`, `tracks`, `merge`), `import` (one import of the whole area's filtered roads; several GB of memory), `tiles` (cut into the 51x34 grid, a tile being its core widened by 0.5 km, written `web/data/metro/<x>_<y>.json`, empty ones skipped) and `index` (`index.json` with checksums, names sorted as text). Measured on the real Montréal data (a developer Mac): import, tiles and pack take about 53 s with 7.3 GB peak memory; 1,718 tiles, about 570 MB of JSON (largest 3.06 MB), archive 571.5 MB.
- `importer`: `import` (an OSM file to a `Network`), `import_whole` (also its frame), `import_in` (limited to a box; the tests' reference), and `merge.rs`. Its tests are one crate, `tests/importer/` (`real_city.rs` follows edits across shifted boxes; `clip_agrees.rs` measures the cut against a clipped import). `cityloom_model::IMPORTER_VERSION` is raised whenever the importer's output changes for the same data.
- CI's deploy job caches `web/data/metro` under a key hashing `src/tiles.rs`, `src/metro_index.rs`, `src/network_tiles.rs`, `src/importer/**` and `cityloom_model/src/**`; a change to any of them makes the tiles again. A change under `crates/citymodel_builder/**` runs every browser spec.
