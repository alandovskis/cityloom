# `citymodel_builder`

Loaded when working in this folder; the root `CLAUDE.md` has the project-wide rules.

- Prepares an area's data, defines the `.citymodel` archive and holds the OpenStreetMap importer (`importer`, the former `osm_import` crate). Workspace crate, not built to wasm (the wasm build excludes it and `cityloom_server`).
- Library `archive` + `metro_index`, deps only `tar`, `sha2`, `thiserror`; the server uses it with default features off. Feature `import` adds the importer (`importer`: osm2streets and its git dependencies, `cityloom_model`); feature `cli` (default) turns on `import` and adds `ureq`, `clap`, `serde_json`, `ctrlc`, and `toml` and `serde` for the cities' configs, for the binary. `network_tiles` is gated on `cli`, not `import`, because it needs `serde_json` and `sha2` beside the importer's types.
- **Archive**: plain ustar tar, deterministic (mtime 0, owner 0, mode 0644, fixed member order): `cityloom.idx` first, then `networks/<x>_<y>.json` (a `NetworkTile`; unpacked as `metro/<x>_<y>.json`).
- **Index**: binary; magic `CLOOMIDX`, version 2 (a version 1 archive, of OSM PBF road tiles, is refused), flags 0. Header (area name, creation time, source name + replication time, grid `lon0`, `lat0`, `dlon`, `dlat` as in `index.json` plus `nx`, `ny`), entries (kind network, `x`, `y`, size, SHA-256, path), SHA-256 trailer over all before it. Max 1 MiB; area name lower-case letters, digits, hyphens, max 64.
- `metro_index` is the one writer of `index.json` (`index_json`), for `tiles` and the server's unpack, so bytes match and keep the shape the app reads (`place/tiles.rs`). Checksums: first 16 hex digits of an entry's SHA-256 (`short_checksum`). `nx`/`ny` are in the archive, not `index.json`.
- Binary modules: `progress` (see `just prepare`: pure frame function, ANSI renderer, plain mode, logs and tails, Ctrl-C restores cursor), `download` (resumable), `city` (a city's config, below), `tiles` (the grid, the margin, their checks and the pipeline's steps), `network_tiles` (cuts the whole network along the grid, writes the JSON tiles), `prepare` (extract, tiles, archive), `commands` (`clap`).
- **Cities**: the source names no city (`tests/city.rs` fails on one). Each city is one file, `cities/<id>.toml`: `id` (the file's name and the archive's area name), `extract_url`, `[grid]` (`west`, `south`, `tile_width`, `tile_height`, `columns`, `rows`) and `[margin]` (`lon`, `lat`). `city::load` reads one of `city::known` (the files' names; an id is compared with them, never made a path), refuses a missing or unknown field, an id the archive refuses or that is not the file's name, a URL whose last part is not a plain `.osm.pbf` name, another city's file giving the same extract name from another URL, and what `tiles::check` refuses (a number not finite, an empty grid, a grid off the earth, a margin under `AREA_REACH_M`, 400 m, at the grid's most poleward edge); each error starts with the file's path and names the field. A city's extract is `data/<extract name>`, its work folder `data/metro-work/<id>`, its archive `data/<id>.citymodel`. `just prepare montreal` prepares Montréal; every file of `cities/` is loaded by a test.
- **Constraint**: everything that turns a config's numbers into tiles stays in `src/tiles.rs` (`CityGrid`, `Margin`, `check`, `metro_bounds`, `steps`, `index`) and `src/network_tiles.rs` (`rect`, `cut`), which the deploy's cache key hashes; `city.rs`, `prepare.rs` and `commands.rs` compute, default or rename no number, only pass those types on. `metro_bounds` and `rect` keep their order of operations, so the same config makes the same bytes.
- osmium stays external. Commands: `prepare <city>` (`--extract <path>` reads another extract, `--refresh` downloads a newer one; no city lists the cities), `tiles <city> [workdir]` (`--extract`; `--out` names the tiles' folder), `pack [<city>]` (the city's area, archive, tiles and extract name unless given; refuses tiles of another grid; without a city, `--area`, `--out`, `--metro` and `--source` are all needed, as `scripts/e2e-archive.sh` gives them), `fixture <in.osm|pbf> <out.json>` (one `NetworkTile` of the input's own frame: the e2e fixtures, `just e2e-fixtures`) and `import <in.osm|pbf> <out.json>` (the whole `Network` as JSON, to look at). No `--batch`.
- The `tiles` steps: osmium filters (`area`, `highways`, `tracks`, `merge`), `import` (one import of the whole area's filtered roads; several GB of memory), `tiles` (cut along the city's grid, Montréal's 51x34, a tile being its core widened by the margin, Montréal's 0.5 km, written `web/data/metro/<x>_<y>.json`, empty ones skipped) and `index` (`index.json` with checksums, names sorted as text). Measured on the real Montréal data (a developer Mac): import, tiles and pack take about 53 s with 7.3 GB peak memory; 1,718 tiles, about 570 MB of JSON (largest 3.06 MB), archive 571.5 MB.
- `importer`: `import` (an OSM file to a `Network`), `import_whole` (also its frame), `import_in` (limited to a box; the tests' reference), `merge.rs` (dual carriageways) and `blocks.rs`. `read_network` runs `convert`, then the carriageways, then `blocks::merge_blocks`, then lays out the lanes and derives the corridors. `blocks.rs` makes the pieces of one block one road, each piece a zone: it merges at a node where exactly two of osm2streets' roads meet (unnamed ones count, so an alley keeps the node), that is not signalled and whose OSM nodes are not tagged `highway=stop|give_way|traffic_signals` (`through_nodes` in `mod.rs`, less any node the carriageway merge folded another into, which `merge_dual_carriageways` returns; osm2streets' kind and its default `Signed` are not used), where two road ends of the network meet, of the same name and type. A ring, or a run whose two ends are one node, is left alone. It raised `IMPORTER_VERSION` to 11. Its tests are one crate, `tests/importer/` (`real_city.rs` follows edits across shifted boxes; `clip_agrees.rs` measures the cut against a clipped import). `cityloom_model::IMPORTER_VERSION` is raised whenever the importer's output changes for the same data.
- Signals (`IMPORTER_VERSION` 12, CLM-31): osm2streets puts signals tagged on a way's approach (Montréal's usual mapping) on the next node it splits the way at; where that is only a split of the way (two roads of one street, the same name and type, as `blocks.rs` joins them; the node not tagged signals nor a signalled crossing), `carry_signals_past_splits` in `mod.rs` moves them on to the first node of three or more roads within `SIGNAL_CARRY_M` (40 m), before osm2streets' transformations drop the split with them. Only signals one road alone faces are carried (signals facing a split from both sides stop traffic at it, as at a crossing); the walk stops at a split with signals of its own, at one that only the road it arrives by faces with signals, and at one osm2streets signalled without placing a stop line, and walks through a split faced from both sides or only from the far side. Known limit: osm2streets also marks a `Signal` stop line for any crossing node in a road's first or last 30%, so a crosswalk there counts as facing signals. `fold_nodes` in `merge.rs` keeps `Signals` when either node of a divided road's junction has it (osm2streets calls every other OSM node `Signed`, never none). Signals mapped only on cycleways and paths are not read: the importer keeps those ways out of osm2streets.
- CI's deploy job runs `just prepare montreal` and caches `web/data/metro` under a key hashing `cities/montreal.toml`, `src/tiles.rs`, `src/metro_index.rs`, `src/network_tiles.rs`, `src/importer/**` and `cityloom_model/src/**` but not its `street/**` and `catalogue.rs` (the street as the editor keeps it; the importer uses neither); a change to any of them makes the tiles again. A change under `crates/citymodel_builder/**` runs every browser spec.
